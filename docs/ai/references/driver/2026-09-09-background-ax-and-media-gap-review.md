后台/AX 固定版本见后文。音频额外检查 oh-my-pi 当次远端 main `856d9375e08dfe79d5e7470e8b92840f1eae772a`；其 `pi-natives/src/audio.rs`、`pi-voice/src/audio.rs` 与此前 `a33cc26824e3c91edd9fa42d681f10dceb4ac2f0` 文件字节一致。后文 OMP AX 仍引用先前审查的 a33 版本，不声称此次完整复审了新 main 的全部桌面代码。这些缺口也不能一概称为上游最近才新增。

### 建议回答“还差多少”的表述

AUV 的 macOS 基础后台投递已经具备，不是要从 0 造一个后台驱动。剩下主要是 **八类工程边界**，其中原表已经覆盖多数；本轮真正展开的新内容是 modifier-click、键盘 auth-envelope 的 toolkit 适配候选、状态 gate、焦点副作用观测/抑制，以及 Windows semantic action ladder。最重的不是包一个参数，而是接收目标与无副作用的可证明性。

不能给百分比。没有同一 macOS/Windows 版本、同一 fixture、同一 front/occluded/minimized/off-Space 状态及同一成功标准的横向运行。CUA 主动拒绝不少背景状态，Peekaboo held-pointer 有 left/right、精确窗口与时限限制；它们不是无条件 background automation。

最小验收建议：
1. AppKit/Electron 独立记录 click down/up/count+modifier；单击 exactly one pair，三击 obey contract，None/explicit-fallback policy 有副作用证据。
2. 同 PID 两个窗口，一个接收焦点；窗口 B 请求不能悄悄改 A，拒绝也验证 A/B 均未变化。
3. visible-unfocused / occluded / minimized / hidden / off-Space 各按 raw pointer、raw key、semantic AX 分别定义允许/拒绝。不能强行全部 pass。
4. 用户持续移动鼠标/切换应用期间动作，before/during/after focus/cursor evidence；恢复不冒充 no disturbance。
5. prefix injection failure + cancellation + same-PID parallel operation，证明无全文盲重放、结果携带 completed/unknown。

不建议把这八组全追加成新的八个 OS issue；标记现有 OS 对应关系，只给真正新参数/平台动作/准入契约建立候选切片。

## AX tree：身份、观察与动作契约

以下是 7 组核心差距与 1 个条件性扩展，均为源码证据。它们细化 OS-04/14/15/16/17/22 等既有候选，不是 8 个新增 bug。AUV 三平台已有 tree backend；重点是将快照、目标身份、局部访问和动作结果连接为可信契约。

### 已有能力与保留边界

- macOS `ObservedAxNode` already exposes role/subrole/title/description/help/identifier/placeholder/value/focused/bounds; tree records app PID and observed_at. However, focused/bounds do not preserve unknown/read-failure states; see AX-3. [model](https://github.com/moeru-ai/auv/blob/bae42bf9905614b19347566d5d41b3a9998e8a35/crates/auv-driver-macos/src/types.rs#L172-L196)
- Windows already captures window-scoped UIA, ValuePattern value, automation_id/class_name; already SetFocus and SelectionItem/Invoke fallback. 系统输出捕获必须另选音源：Windows 官方说明要求 rendering endpoint + loopback 初始化，而普通捕获用 capture endpoint。[Microsoft WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)。将虚拟回环设备设为默认输入，可能让普通输入采集间接收到系统声音，但不等于框架实现原生 loopback 或应用级音频选择。

CUA 上述 SCKit video config 没有启用音频的配置，不能把其 MP4 默认认定为有声录屏。它的 [FFmpeg 输入](https://github.com/trycua/cua/blob/467c103be28384502cdd77b9edd5ea46da0b8ded/libs/cua-driver/rust/crates/cua-driver-core/src/video_ffmpeg.rs#L292-L325) Windows 用 gdigrab、Linux 用 x11grab，也不构成 Wayland 通用录屏证据。AUV 已有的 [OBS 平台捕获研究](2026-08-05-obs-platform-capture-backends-research.md) 可以复用作为后续选型依据，不必重新发明全部 capture backend。

MEDIA-1 最小验收：选择一个确切 target，录制已知动画并解码检查帧/时序；正常 stop、取消、编码失败分别验证 artifact 可读或明确 incomplete；录制与 run 时间线可关联。不要用“文件存在”作为完整性测试。

MEDIA-2 最小验收：已知应用输出音调、麦克风保持静默，验证采集来自指定输出；若承诺 app scope，还要另一 app 同时发声验证隔离。MEDIA-3 使用可控输入 fixture 验证采样率/顺序和重复 stop 释放；跨线程消费需要有界缓冲与丢样证据。单独录音不应为了未来音画同步先造总调度器。
